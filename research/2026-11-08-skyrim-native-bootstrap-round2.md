# Skyrim native bootstrap audit, 8 November 2026

Subject: static inspection of the privately prepared owned x86-64 Skyrim PE and previously recorded Mac strict-AOT probe009; no new game execution or compatibility claim.

The prepared image (`8daf05196ecad57963be61614ce4a4cd5c4dc27d222db14e01c262b36b3d46d4`) imports exactly `VR_InitInternal2`, `VR_GetInitToken`, `VR_IsInterfaceVersionValid`, `VR_GetVRInitErrorAsEnglishDescription`, `VR_ShutdownInternal`, and `VR_GetGenericInterface` from `openvr_api.dll` (MinGW `objdump -p`). The error-description import is required even though the initialization trace does not instrument it. Static flow and probe009's actual interface requests are detailed in [the earlier report](2026-11-08-skyrim-no-image-stop.md). System019 slot 18 is `GetTrackedDeviceIndexForControllerRole`; Compositor022 is observed after the failed initialization. Additional version strings in the binary are not observed requests.

Read-only disassembly of the game's Valve DLL (`d079238dae5a1cbfbcba014b644ad550a5c8c088007097a463a94b6ad6f7e184`) shows `VR_InitInternal` delegates to InitInternal2 with null startup; InitInternal2 invokes ClientCore Init and returns zero on failure, or increments and returns a 32-bit generation on success. `VR_GetInitToken` reads this generation. Shutdown cleans up the core and increments the generation even when no core exists. Before a core exists, GetGenericInterface returns null and error 109, and IsInterfaceVersionValid returns false. A prospective export façade must provide guest-callable ABI stubs, actual native core errors, version-specific guest objects, and lifetime-sensitive generation semantics; it must not present a raw native vtable. Further repeated-init and concurrent lifecycle behavior needs explicit owned tests.

In probe009, OpenVR InitInternal2 entered at 12:04:03.812, before D3D11CreateDeviceAndSwapChain succeeded at 12:04:03.925; the latter occurred after Valve initialization failed. A successful native initialization could alter control flow and has not been measured. Native provider bootstrap must therefore handle a missing guest D3D11 device at Init. The proposed provider-first device and copy queue must match the later D3D device, and a separate D3D producer queue must be explicitly flushed and completed before copy; the copy must also complete before publication. The isolated fixed-size fixture host is not a game host.

Private prepared EXE and extracted DirectX DLLs were copied into this checkout's ignored `build/private/skyrimvr/6961efb4f4775a307b0fc9a3d637542c1e090be207d3b09467eab216b7f87971/` only after matching the recorded SHA-256 and rehashed afterward. No original was modified. Probe009's manifest lists 18 immutable translated dylibs; all 18 still match its recorded hashes. Its startup log reports the prepared EXE parts at base `0x140000000`, bink `0xf00000000`, Valve OpenVR `0xf01000000`, Steam API `0xf02000000`, msvcp `0xf03000000`, d3dx `0xf04000000`, and X3DAudio `0xf05000000`. Actual image identity and base must be revalidated against any new loader configuration; the Valve AOT module is irrelevant if the explicitly selected builtin replaces it. These historical log records and hashes do not by themselves establish the original compiler source identity or zero fallback in a new run.

The delegated Makefile fix corrects the owned init fixture's import-library search path; `make -C VXRuntime build/recomp/openvr-init-check-fixture/aot_openvr_init.exe` exits 0 from a fresh build directory. This is compilation only, not a runtime or game test. Game probing remains gated on the joined guest stereo/provider proof, usable host bootstrap, runtime checks and coordinator clearance.
